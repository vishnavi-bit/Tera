# DB design
Target DB: SQLite 3.x (libSQL, as used by apps/api; file:./data/app.db)
Constraints:
- Naming: snake_case, plural table names; FK columns `<singular table>_id`.
- Ids: TEXT UUID, generated by the app.
- Common columns on every tenant table, omitted in the sections below: `id` TEXT PK; `tenant_id` TEXT NOT NULL FK -> tenants.id, indexed; `created_at`, `updated_at` TEXT UTC ISO 8601.
- Tenancy: every query filters on tenant_id. Unique keys include tenant_id unless the section says otherwise.
- Reference tables (price_tiers, product_types, user_roles, payment_modes, customer_types, service_job_types) have a code PK and no tenant_id: shared lists (deviation from the tenant rule).
- Money: INTEGER in paise (no floats). Quantities INTEGER. Booleans INTEGER 0/1 with CHECK. Dates TEXT (YYYY-MM-DD).
- Enums: TEXT with CHECK, values listed in the Constraints column.
- Soft delete: `deleted_at` TEXT on master data (sections marked). Transactions are never hard-deleted.
- 3NF: derived values are not stored (invoice paid or pending, ledger balance, dealer vehicle stock, shortfall). Stored balances only for spare stock (unit_spare_stock, dealer_spare_stock), by design.
- Dealer owner = user with role owner and dealer_id set. There is no separate dealer login table.
- Serial numbers (chassis, motor, battery, controller) are unique per tenant.
Sources: docs/requirements REQ-367 to REQ-403 (req.md and mock.md); docs/project/intent.md; docs/mock/apps/tera-ev (roles.json, mock-data/spec/screens.json).
Tables: db_design_tables.csv (Status: New = proposed by Claude · Feedback = open feedback to apply or answer · Final = accepted)
