Cross-cutting proposals (apply to several screens)

  • Unit identifiers. Both sample invoices show each unit carries chassis, motor, controller and battery numbers (Jitendra: one row per unit with Battery No, Color, Controller No, Motor No, Chassis No; Tera: "Chassis Number" in Notes). Proposed unit record: chassisNo (unique), motorNo, controllerNo, batteryNo[], chargerNo, colour, variant, productionDate, status. N04 creates it, N05/N27/N07 read it, D20 binds it to a customer.
  • Status trail of a unit: Built, QC passed, In stock, Reserved (Assigned), Billed (OK to Bill), PDI done, Dispatched, Delivered. Each change writes an audit-log row (O54).
  • Roles follow docs/people.md and the existing role codes (e.g. oem-production-mgr, oem-logistics-mgr). New roles are only introduced by N28.
  • Common buttons on every create/edit form: Save draft, Submit, Cancel; every list: search, filter, export.
  • Validation style follows the spec: required marked, inline errors, 7-char user IDs untouched.
